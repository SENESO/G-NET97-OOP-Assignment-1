Question 1:
a) What happens when a DeliveryAddress variable is copied into another variable and the copy is modified?
   Answer: Because DeliveryAddress is a struct (value type), copying it creates an independent copy of the data. Modifying the copy will not affect the original DeliveryAddress variable.
   
b) What happens when a Customer variable is copied into another variable and one variable modifies the object?
   Answer: Because Customer is a class (reference type), copying it only copies the reference (memory address), not the actual object data. Both variables will point to the same object in memory, so modifying the object through one variable will affect the other.

Question 2:
a) Identify at least three problems with this design from an encapsulation perspective:
   Answer:
   1. Public fields (Description, Weight, DeliveryFee) break encapsulation as they can be modified from anywhere without validation.
   2. No validation logic is enforced when assigning values (e.g., Weight or DeliveryFee could be set to negative values).
   3. Internal state is completely exposed, meaning the struct cannot change its internal implementation without breaking the code that depends on it.

b) How can private fields and public properties improve this design?
   Answer: 
   By using private fields, the data is hidden and protected from unauthorized access. 
   Public properties provide controlled access, allowing validation logic within the `set` accessor (e.g., ensuring weight > 0). 
   This also enables making fields read-only by omitting the `set` accessor if needed.
